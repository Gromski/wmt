<objective>
Make YouTube fallback tracks position-aware so they land in their true round-robin slot AND the surrounding Apple Music tracks get re-attributed correctly. Plan 03-04 inserted each fallback as its own row but APPENDED it at the session end with Apple positions untouched. Live-data investigation (see the design spec) showed that a fallback is a pick MISSING from the person-cycling Apple playlist, so today's `initials[(position-1) % N]` round-robin shifts and misattributes every Apple track after the gap (e.g. S3: all 14 Apple tracks currently attributed to the wrong person).

Authoritative design: `docs/superpowers/specs/2026-08-10-position-aware-fallback-tracks-design.md` (approved 2026-08-10). Playlists are person-cycling by round; the starting person is encoded by the ORDER of the initials list; every person contributes 4 tracks (last→round 4). The description declares each fallback's ordinal; the importer trusts it and reconstructs the grid.

This plan lands the parser + pure positioning helper + import-route rewrite and their tests. The human step (updating descriptions to the new ordinal/bonus convention, re-importing, spot-checking) is plan 03-05, re-sequenced after this.

Purpose: Correct BOTH fallback placement and Apple-track attribution in sessions that have YouTube fallback picks.
Output: `parseFallbackTracks` entries carry a `round`; a tested pure `buildSessionTrackPositions` helper; an import route that reconstructs the grid and attributes every grid track by position.
</objective>

    - If initials is null → NO reconstruction: applePositions = 1..appleCount; every fallback is bonus appended after (position appleCount + k + 1, in order). demotions empty.

      * Apple tracks fill positions 1.. in order, skipping positions occupied by surviving grid fallbacks.
      * Bonus fallbacks (round == null OR demoted) appended after the max used position, in description order.
    Positions returned are 1-based and unique across the session.
