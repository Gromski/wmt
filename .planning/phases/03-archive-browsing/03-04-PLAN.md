<objective>
Fix the mis-modelling of YouTube fallback tracks (UAT test 4, gap BROWSE-03). Today the import route writes a session's single parsed YouTube URL onto the FIRST track lacking an appleId (else position 1) as an extra link on an existing Apple Music track. This is wrong in three ways: (1) it only captures the first URL (S3 has two), (2) it attaches the URL to whatever track happens to sit at position 1 rather than the person who chose it (S31 attaches Jonny's/JS diamond track onto Iwan's/IT position-1 track), and (3) it never models the fallback track as its own entry.

Per the authoritative user resolution in 03-UAT.md (`## Gaps` → `resolution:`, dated 2026-08-10), each fallback track is its OWN track — attributed to the NAMED person, with title/artist parsed FROM the description (NO external/YouTube fetch), from the canonical format:

  "<Name>'s <descriptor> track: <Artist> - <Title> <url>"

Multiple per description are separated by " / ". This plan lands the parser + import-route changes and their tests. The human step (updating the actual Apple Music descriptions + re-importing + spot-checking) is plan 03-05, sequenced after this.

Purpose: Correct the data model so fallback tracks land on the right person in the right session.
Output: A new `parseFallbackTracks` extractor with tests; an import route that inserts fallback tracks as their own rows with explicit named-contributor attribution.
</objective>
