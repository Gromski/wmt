export type ContributorAnalytics = {
  initials: string;                                  // "MW" | "JG" | "JS" | "IT"
  name: string;

  genreVector: Record<string, number>;               // genre -> track count incl "Unspecified" (Plan 02)
  profileVector: Record<string, number>;             // "genre:X" / "decade:Y" -> weighted proportion (Plan 02 wildcard)
};

export type AttributedRow = {
  contributorInitials: string;
  contributorName: string;
  sessionId: number;
  artistName: string;

};

export type AnalyticsData = {
  contributors: ContributorAnalytics[];              // ordered MW, JG, JS, IT

};

export async function getAnalyticsData(): Promise<AnalyticsData>;

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client → `/analytics` RSC | Untrusted request crosses here. Route is intentionally public (ACCESS-04 / D-13), read-only, takes NO user-supplied parameters (no searchParams, cookies, or form input in the MVP hub). |
| App → `local.db` (Drizzle) | Aggregation queries are static and parameterised by Drizzle's query builder; no user input reaches any query. |
| Build → npm registry | `npx shadcn add chart` pulls `recharts` from npm. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | Drizzle queries in `lib/analytics.ts` | accept | No raw SQL and no user-supplied query parameters — all filtering is static; Drizzle builder is parameterised by construction. No injection surface. |
| T-04-02 | Information Disclosure | `/analytics` error output | mitigate | Contributor names/artists are already public (Phase 3). Rely on Next.js default production error boundary — no secrets, tokens, or PII are read on this route; introduce no verbose custom error page. |
| T-04-03 | Denial of Service | Single unindexed full-table aggregation per request | accept | Dataset is fixed and tiny (~474 session_tracks, ~1937 tag rows); route is statically renderable (no dynamic APIs) so it is not recomputed per request under Next's default caching. |
| T-04-SC | Tampering (supply chain) | `recharts` install via shadcn CLA | mitigate | `recharts` was slopcheck `[OK]` / Approved in RESEARCH § Package Legitimacy Audit (10.5 yrs old, 56.9M weekly downloads, `github.com/recharts/recharts`). Not `[ASSUMED]`/`[SUS]` → no blocking human checkpoint required. Executor installs the exact CLI-resolved version. |
</threat_model>
