<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → POST /api/import | Untrusted request; client may have crafted the request directly without going through the UI. Server must enforce all gates here. |
| Dashboard Server Component → conditional render of ImportTrigger | Server decides whether to render the Card based on `session.user.role`. Member clients never receive the Card markup. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Elevation of Privilege | Member crafts direct POST /api/import bypassing the UI gate | mitigate | API route Task 1 re-checks `session.user.role !== "admin"` and returns 403. Defense-in-depth per RESEARCH Anti-pattern lines 420-421. UI gate (server-side render conditional) is the convenience; API gate is the enforcement. |
| T-03-02 | Spoofing | Unauthenticated POST /api/import | mitigate | Task 1 returns 401 when `auth.api.getSession` returns null. |
| T-03-03 | Information Disclosure | Error message reveals whether email exists vs whether role check failed | mitigate | The 403 body is the generic `{error: "Forbidden"}` — does not reveal whether the user does not exist, or exists with wrong role. The 401 body is `{error: "Unauthorized"}` — generic. |
| T-03-04 | Tampering | Member edits the dashboard React tree client-side to make `<ImportTrigger />` render | mitigate | Even if member fabricates the Card client-side, the API call returns 403. The UI gate is render-side only; the only true gate is the server-side 403 from the route handler. RESEARCH Anti-pattern lines 420-421. |
| T-03-05 | Denial of Service | Repeated POST /api/import spamming session DB lookups | accept | Phase 1 returns immediately (no actual import work); a member sees 403 instantly without DB work beyond the session check. Phase 2 will need rate limiting when the route does real work — flagged as a Phase 2 concern in the PHASE 2 TODO comment in Task 1. |
| T-03-06 | Repudiation | No audit log of who triggered an import | accept | Phase 1 is single-tenant (4 friends, 1 admin); audit logging is disproportionate. Phase 2 may add a `import_log` table when real imports run. |
| T-03-07 | Input Validation | Phase 1 stub accepts no body; future Phase 2 implementation might forget Zod validation | mitigate | PHASE 2 TODO comment in route.ts explicitly flags "Validate request body with Zod (V5 Input Validation)". The Plan 03 SUMMARY will surface this TODO to the Phase 2 planner. |
</threat_model>
