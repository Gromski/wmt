## Phase Goal

**As an** admin, **I want to** trigger an import that pulls all my Apple Music sessions, parses contributor attribution, enriches genres, and lets me edit session dates and fix attribution gaps inline on the dashboard, **so that** the archive is populated from authoritative streaming data without me having to hand-key 31 sessions × 16 tracks.

<objective>
Lay the foundation for the Phase 2 import slice: extend the Drizzle schema with the five app-specific tables, build the server-only Apple developer token utility + GET route that vends it to authorised admins, declare the MusicKit JS global type, and install the new shadcn primitives the later plans will compose. A blocking Wave 0 checkpoint first verifies the human has the Apple Developer credentials available (per RESEARCH §Open Questions OQ-3 RESOLUTION and CONTEXT D-05) — without them no downstream work can succeed.

Purpose: All three Phase 2 plans depend on (a) Apple Developer credentials being present so the developer token can be generated, (b) the schema being in place so inserts in 02-02 succeed, (c) a working `/api/apple-token` endpoint so the browser-side MusicKit flow in 02-02 can configure itself, and (d) Table/Alert/Select/Progress/Tooltip components so 02-02 and 02-03 can build the UI. Doing this as one foundational plan keeps the next two plans focused on user-visible behaviour.

Output: Verified Apple credentials in .env.local (Task 0 prerequisite), db/schema.ts extended (committed + pushed), lib/apple-dev-token.ts, app/api/apple-token/route.ts, types/musickit.d.ts, five new shadcn UI primitives, BLOCKING schema push complete.
