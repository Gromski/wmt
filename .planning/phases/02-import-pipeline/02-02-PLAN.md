## Phase Goal

**As an** admin, **I want to** trigger an import that pulls all my Apple Music sessions, parses contributor attribution, enriches genres, and lets me edit session dates and fix attribution gaps inline on the dashboard, **so that** the archive is populated from authoritative streaming data without me having to hand-key 31 sessions × 16 tracks.

<objective>
End-to-end vertical slice: clicking "Start import" on /dashboard runs the full Apple Music import — MusicKit authorisation in the browser, server-side playlist + track fetch with attribution parsing, batch DB replace, then Last.fm artist tag enrichment — and the browser sees real-time progress. After this plan, sessions and tracks exist in local.db; IMPORT-01, IMPORT-02, IMPORT-03, IMPORT-04, IMPORT-06, IMPORT-07, and IMPORT-08 are all data-level true.

Purpose: This is the happy-path slice the MVP user story hinges on. A real user (Mark) can perform the action they could not perform after Phase 1: actually populate the archive from Apple Music. Subsequent plan 02-03 layers the date entry + attribution review UI on top, but the import itself is provable here.

Output: Replaced `/api/import` (SSE streaming POST), replaced `ImportTriggerCard` (MusicKit + progress bar + D-04 warning), three new server-side helper libs.
</objective>
